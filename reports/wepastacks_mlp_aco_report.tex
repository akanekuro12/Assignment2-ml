\begin{abstract}
This project studies whether recent inbound activity can predict warehouse-buffer congestion early enough to support proactive transport decisions. The real WEPAStacks event stream contains 205,258 inbound pallet events across relative days 2--89. Events are aggregated into 15-minute intervals for four inbound points. A compact multilayer perceptron (MLP) uses current buffer utilisation, current arrivals, a 60-minute rolling arrival rate, and a one-hot dock identifier to predict whether a simulated queue will reach 80\% of capacity during the next 60 minutes. The verified baseline contains 801 trainable parameters and achieves 98.66\% accuracy, 98.39\% precision, 90.55\% recall, 94.31\% F1, and 97.32\% average precision on the chronological test set. These results apply to a simulated congestion target and provide strong evidence mainly for Dock~1, because Docks~2--4 have no positive examples in validation or test.

The project also implements a risk-aware ant colony optimisation (ACO) layer that converts predicted risk into feasible multi-drone pickup routes under payload and return-battery constraints. The four remote warehouses, their capacities and coordinates, the central depot, and the drone fleet are simulated experimental assumptions; they are not properties of the WEPAStacks dataset. The routing implementation passes ten unit tests covering leakage control, queue updates, determinism, payload, battery, demand, and route feasibility. However, no completed end-to-end operational comparison is available in the supplied outputs. Consequently, this report treats the MLP metrics as experimental findings and the MLP--ACO system as an implemented, constraint-tested framework whose operational benefit remains an open empirical question.
\end{abstract}

\textbf{Keywords:} warehouse congestion, multilayer perceptron, time-series classification, class imbalance, ant colony optimisation, drone routing, WEPAStacks

\section{Introduction}

Inbound congestion occurs when arriving goods accumulate faster than a warehouse handling system can remove them. A useful warning system must detect risk before the buffer is full, while a useful transport policy must turn that warning into a feasible action. This project links these two tasks. The MLP estimates the risk that a dock will reach a congestion threshold within one hour. A routing layer then uses that risk to decide which simulated satellite warehouses should be served and how a small fleet of drones should visit them.

The practical motivation is that a purely reactive policy waits until the buffer is already close to full. If congestion can be forecast from the current queue and recent arrivals, a vehicle can be dispatched earlier. Machine learning is suitable because the relationship between bursty arrival patterns, queue state, dock identity, and near-future congestion is nonlinear. A fixed threshold on the current fill ratio cannot represent all of these interactions. A small MLP is used instead of a larger sequential model because the feature set already summarises the recent 60-minute history, the dataset is tabular, and the model must remain easy to inspect and deploy.

The central research question is:

\begin{quote}
Can current buffer utilisation and recent inbound arrivals predict simulated congestion in the next 60 minutes, and can that risk signal be converted into feasible resource-constrained pickup routes?
\end{quote}

The supplied evidence answers the first part positively within the present simulator and test distribution. The second part is only partially answered: route feasibility is implemented and tested, but the operational comparison against reactive baselines has not yet been produced.

\subsection{Training interface}

Each training observation represents one dock at the end of a 15-minute interval. The input vector is
\begin{equation}
\mathbf{x}_{i,t} = [r_{i,t},\; a_{i,t},\; \bar{a}^{(60)}_{i,t},\; d_{i,1},\; d_{i,2},\; d_{i,3},\; d_{i,4}] \in \R^7,
\end{equation}
where $r_{i,t}$ is the buffer fill ratio, $a_{i,t}$ is the current number of arrivals, $\bar{a}^{(60)}_{i,t}$ is the mean arrival count over the current and previous three intervals, and $d_{i,j}$ is a one-hot dock indicator. All input values are available at or before time $t$.

The binary training target is
\begin{equation}
y_{i,t}=\mathbb{1}\!\left[\max_{h\in\{1,2,3,4\}} Q_{i,t+h} \geq 0.8K_i\right],
\label{eq:target}
\end{equation}
where $K_i$ is buffer capacity. In the verified baseline, $K_i=20$ and the positive threshold is 16 units. Future queue values are used only to construct the historical label. They never appear in the input vector.

\subsection{Expected behaviour}

Given a low fill ratio and low recent arrivals, the MLP should produce a low risk score. A high or rapidly increasing queue should raise the score even if the current fill ratio has not yet reached 80\%. The ideal classifier detects most future congestion cases without producing excessive false alarms. In routing deployment, a high-risk warehouse may become active before it is physically full. Every proposed route must begin and end at the central depot, stay within payload and available-battery limits, collect only from visited warehouses, and never collect more than the requested demand.

\section{Dataset and Preprocessing}

\subsection{Dataset structure and quality}

The cleaned dataset contains 205,258 inbound events and nine fields: arrival time, relative day, hour, minute, 15-minute time bin, dock, SKU, batch, and week. It covers relative days 2--89. Basic checks found no missing values, no invalid dock identifiers, no negative arrival times, and no fully duplicated rows. The derived day, hour, minute, and time-bin fields are consistent with arrival time. There are 4,763 repeated arrival-time and dock combinations, but these are not removed because multiple distinct cargo events may occur at the same dock in the same second.

The main data-quality issue is representativeness. Dock~1 contains 93.26\% of all events, while Docks~2--4 disappear early in the timeline. After day~39, all observed events belong to Dock~1.

\subsection{Aggregation and zero intervals}

Arrival time is divided by 900 seconds and rounded down to obtain a 15-minute time bin. Events are grouped by time bin and dock. A complete Cartesian grid is then created from all 8,395 consecutive time bins and the four docks, producing 33,580 dock--interval rows before rolling and future-horizon exclusions. Missing counts are filled with zero. This step is necessary because a missing event row may mean that an active dock received no goods during the interval.

The same operation also creates a limitation. For Docks~2--4, a zero after the final recorded event may mean either zero demand or missing/inactive coverage. The dataset has no \texttt{dock\_active} field, so the pipeline cannot distinguish these cases. The report therefore treats late zero rows for Docks~2--4 cautiously.

\subsection{Rolling features, queue simulation, and leakage control}

The 60-minute rolling feature is the mean of arrivals in the current and previous three intervals. The first three rows for each dock are discarded because a complete window is unavailable. The verified MLP baseline estimates a fixed service rate from the training period only:
\begin{equation}
S_i = \max\left(1,\left\lceil 1.10\,\overline{a}_{i,\mathrm{train}}\right\rceil\right),
\end{equation}
which gives 25, 2, 1, and 1 units per 15 minutes for Docks~1--4. The queue update is
\begin{align}
R_{i,t} &= \max(0,Q_{i,t}+a_{i,t}-S_i),\\
O_{i,t} &= \max(0,R_{i,t}-K_i),\\
Q_{i,t+1} &= \min(K_i,R_{i,t}).
\end{align}

The final four rows for each dock are discarded because they do not have a complete future label horizon. The resulting modelling table contains 33,552 observations. Leakage is controlled by using only current and past arrivals as features, fitting the service rate and scaler on training data, inserting one-hour gaps at split boundaries, choosing the classification threshold on validation data, and reserving test data for final evaluation.

\subsection{MLP architecture}

The network has two hidden layers. The first maps seven inputs to 32 ReLU units, followed by 20\% dropout. The second maps 32 values to 16 ReLU units. A single sigmoid output produces a risk score. Glorot uniform initialisation is used for the dense-layer weights, and all biases start at zero.

The forward pass can be written as
\begin{align}
\mathbf{h}_1 &= \operatorname{ReLU}(\mathbf{W}_1\mathbf{x}+\mathbf{b}_1),\\
\widetilde{\mathbf{h}}_1 &= \operatorname{Dropout}_{0.2}(\mathbf{h}_1),\\
\mathbf{h}_2 &= \operatorname{ReLU}(\mathbf{W}_2\widetilde{\mathbf{h}}_1+\mathbf{b}_2),\\
\hat{p} &= \sigma(\mathbf{w}_3^\top\mathbf{h}_2+b_3).
\end{align}

This structure is small enough to inspect yet able to model nonlinear interactions. ReLU avoids the saturation of sigmoid hidden units, dropout limits co-adaptation, and the sigmoid output matches binary classification. These choices follow standard feed-forward neural-network practice \cite{rumelhart1986,glorot2010,srivastava2014}.

\subsection{Loss, optimiser, and class imbalance}

The network minimises weighted binary cross-entropy:
\begin{equation}
\mathcal{L}_{\mathrm{BCE}}=-\frac{1}{N}\sum_{n=1}^{N}w_{y_n}
\left[y_n\log \hat{p}_n+(1-y_n)\log(1-\hat{p}_n)\right].
\label{eq:bce}
\end{equation}
Balanced weights computed from the training labels are $w_0=0.6095$ and $w_1=2.7833$. A positive error therefore has approximately 4.57 times the weight of a negative error. Adam is used with learning rate $10^{-3}$, $\beta_1=0.9$, $\beta_2=0.999$, and $\epsilon=10^{-7}$ \cite{kingma2015}. Training uses mini-batches of 256, at most 100 epochs, and early stopping on validation loss with patience eight and restoration of the best weights.

\subsection{Risk-aware ACO routing}

The drone study maps the four inbound points to four simulated satellite warehouses and adds a central depot. At interval $t$, available goods are the previous queue plus current arrivals. A warehouse is active when it contains goods and either its predicted risk exceeds a risk threshold or its current fill ratio exceeds the fill threshold. Urgency combines predicted risk and current fill:
\begin{equation}
u_{i,t}=0.60\,\hat{p}_{i,t}+0.40\min(1,r_{i,t}).
\end{equation}

An ant chooses a feasible next warehouse using pheromone $\tau_{ij}$ and heuristic desirability $\eta_{ij}$:
\begin{equation}
P(i\rightarrow j)=\frac{\tau_{ij}^{\alpha}\eta_{ij}^{\beta}}
{\sum_{k\in\mathcal{F}}\tau_{ik}^{\alpha}\eta_{ik}^{\beta}},
\qquad
\eta_{ij}=\frac{\varepsilon+u_j}{\varepsilon+d_{ij}},
\end{equation}
where $\mathcal{F}$ contains only warehouses that can be visited without violating payload or the energy required to return to the depot. The implementation uses $\alpha=1$, $\beta=2$, 30 ants, at most 100 iterations, evaporation 0.10, and a stall limit of 20 iterations. Pheromone is clipped to a fixed numerical range. This follows the constructive and iterative logic of ant-colony routing \cite{dorigo1997}.

The ACO objective is
\begin{equation}
J=0.30\frac{E_{\mathrm{used}}}{\sum_d B_d+\varepsilon}
+0.70\frac{\sum_i u_iR_i}{\sum_i u_iD_i+\varepsilon},
\label{eq:aco-objective}
\end{equation}
where $D_i$ is active demand and $R_i$ is remaining demand after pickup. The constraints are
\begin{align}
\sum_i x_{d,i} &\leq C_d^{\mathrm{payload}},\\
E(\text{route}_d) &\leq B_d^{\mathrm{available}},\\
x_{d,i} &>0 \Rightarrow i\in\text{route}_d,\\
\sum_d x_{d,i} &\leq D_i.
\end{align}
Every route starts and ends at node 0. The battery check includes the energy required to return from a candidate warehouse, rather than checking only the next leg.

\subsection{Evaluation metrics}

Accuracy alone is unsuitable because only 12.24\% of test observations are positive. Precision measures how many warnings are correct. Recall measures how many congestion events are detected. F1 balances precision and recall. Balanced accuracy averages sensitivity and specificity. Average precision summarises the precision--recall curve and is more informative than accuracy when the positive class is rare \cite{saito2015}. ROC--AUC is also reported, but it can appear optimistic under severe imbalance. The confusion matrix keeps the operational meaning of false alarms and missed congestion visible.

For routing, the planned metrics are total overflow, total collected goods, energy, distance, number of sorties, percentage of active demand left behind, algorithm runtime, and constraint violations. A complete comparison should report mean and standard deviation across ten ACO seeds and compare nearest-first, fullest-first, ACO using only current fill, and MLP--ACO. These operational outputs were not present when this report was generated.

The supplied repository contains no completed \code{outputs/tables/baseline_comparison.csv} and no compatible \code{model_outputs_aco} artifacts. \section{Discussion}

\subsection{Answer to the research question}

The MLP provides a strong predictive baseline for the simulated congestion label. It improves substantially over the always-negative accuracy baseline, retains high recall at very high precision, and shows only mild overfitting. Within the observed Dock~1 test regime, recent arrivals and current queue state contain enough information to predict the next-hour threshold crossing.

The second part of the research question remains open. A risk-aware ACO policy is implemented and its solutions are checked for feasibility, but no end-to-end comparison demonstrates that using predicted risk improves overflow, collection, or energy. The report therefore supports feasibility of the integration, not operational benefit.

\subsection{Training loss versus the practical objective}

Binary cross-entropy and the operational objective answer different questions. BCE rewards accurate probabilities for the simulated label. Warehouse operation cares about missed congestion, overflow volume, unnecessary sorties, energy, and uncollected goods. A model can reduce BCE without improving a specific operating point. For example, shifting a positive score from 0.96 to 0.90 can improve calibration yet turn a correct alert into a false negative under the selected threshold of 0.9583. Conversely, an overconfident score can trigger an energy-consuming trip even when no overflow would occur.

The project mitigates this mismatch in three ways. First, it reports precision, recall, F1, average precision, and the confusion matrix in addition to loss. Second, it selects the classification threshold on validation data rather than fixing 0.5. Third, the routing layer uses a separate objective that penalises risk-weighted remaining goods and normalised energy. The mismatch is not fully resolved because the MLP is trained independently of downstream routing cost. A stronger future method would select the alert threshold using explicit costs or train a decision-aware model whose loss approximates expected overflow and dispatch cost.

\subsection{Implications}

The high Dock~1 performance suggests that a small feed-forward network can be sufficient when queue state and short rolling history are informative. This is valuable because the model is inexpensive to train, easy to deploy, and simple enough to explain during assessment. The selected threshold produces very few false alarms, but the 64 missed positive cases remain important. If overflow is more costly than an unnecessary trip, the operating threshold should favour recall rather than maximum F1.

The data also show why a technically correct pipeline can still support an overly broad claim. Chronological splitting prevents temporal leakage, yet the future period contains almost no evidence about three docks. Correct evaluation procedure does not compensate for missing coverage. The deployment claim must match the support in the held-out data.

\subsection{Limitations}

\begin{enumerate}
  \item \textbf{Simulated target.} Queue length and congestion are generated from assumed service rates and buffer capacity. The model predicts the simulator, not directly observed warehouse congestion.
  \item \textbf{Dock coverage shift.} Docks~2--4 end early. Validation and test cannot measure their positive-class recall, F1, or AUC.
  \item \textbf{Ambiguous zero intervals.} Missing or inactive coverage is encoded in the same way as an active dock with zero arrivals.
  \item \textbf{Dominant Dock 1.} Dock~1 contains 93.26\% of inbound events, so a shared model is driven mainly by its operating pattern.
  \item \textbf{Uncalibrated score.} Weighted BCE and F1-based threshold selection can produce useful ranking without producing a calibrated probability.
  \item \textbf{Limited feature set.} The baseline excludes hour-of-day, shift, robot state, downtime, service completions, and SKU mixture.
  \item \textbf{Different queue models.} The verified MLP artifacts use a fixed service-rate queue with capacity 20. The drone-only pipeline uses larger simulated capacities and removes goods only through pickup. The old model must not be inserted into the new simulator without retraining.
  \item \textbf{Simplified drone physics.} The routing model omits weather, no-fly zones, collision avoidance, three-dimensional trajectories, charging schedules, and time windows.
  \item \textbf{No operational result table.} Constraint tests validate implementation behaviour, but they do not measure policy quality over the held-out stream.
\end{enumerate}

\section{Recommended Refinements}

The highest-priority improvement is to obtain data that distinguish an active dock with no arrivals from an inactive or unobserved dock. A \texttt{dock\_active} field, operating calendar, and verified reason for the early termination of Docks~2--4 would make the temporal grid meaningful. Real queue length, service completions, incident logs, and confirmed capacities would allow Eq.~\eqref{eq:target} to be replaced or validated against an observed target.

Model evaluation should preserve chronological splits and report support for every metric. After using the current test findings to change the pipeline, a new untouched test period should be reserved. Probability calibration should be assessed on validation data using a reliability diagram and Brier score. Threshold selection should reflect the cost of false negatives, overflow, and unnecessary dispatches rather than F1 alone.

The next model study should compare the current seven-feature MLP with interpretable baselines such as logistic regression and a current-fill threshold, then test time-of-day sine/cosine features, short-window trend and variance, and dock-activity indicators. More complex sequential models are justified only if they deliver a measurable improvement under the same chronological protocol.

For routing, the complete experiment should first train the drone-compatible MLP using the same capacities and historical queue policy as deployment. It should then run nearest-first, fullest-first, ACO-current, and MLP--ACO on identical copies of the held-out arrival stream. ACO policies should use the ten configured seeds. Results should include mean, standard deviation, and confidence intervals for overflow, goods collected, energy, distance, remaining active demand, sorties, and runtime. Small active instances should be checked against the exact solver to quantify the ACO optimality gap.

\section{Conclusion}

The verified MLP is a compact and effective predictor of the current simulated congestion target. With 801 trainable parameters, it reaches 94.31\% test F1 and 97.32\% average precision under a leakage-aware chronological protocol. Its strongest evidence is for Dock~1. The result does not establish performance for congestion at Docks~2--4 or for real warehouse queues because those cases are not represented in the held-out labels and the target is simulated.

The risk-aware routing framework is technically coherent: it converts current state and predicted risk into multi-drone routes, enforces payload and return-battery constraints, updates queues chronologically, and passes all supplied unit tests. Its operational value has not yet been measured. A complete project conclusion requires a drone-compatible trained model and a multi-seed comparison against reactive baselines. Until then, the correct claim is that the project demonstrates strong simulated congestion prediction and a feasible path from prediction to routing, not proven end-to-end operational improvement.

\section{Metric Definitions}

For true positives $TP$, false positives $FP$, true negatives $TN$, and false negatives $FN$:
\begin{align}
\mathrm{Precision} &= \frac{TP}{TP+FP}, &
\mathrm{Recall} &= \frac{TP}{TP+FN},\\
\mathrm{Specificity} &= \frac{TN}{TN+FP}, &
\mathrm{F1} &= \frac{2\,\mathrm{Precision}\,\mathrm{Recall}}
{\mathrm{Precision}+\mathrm{Recall}},\\
\mathrm{Balanced\ Accuracy} &= \frac{\mathrm{Recall}+\mathrm{Specificity}}{2}.
\end{align}
The Brier score is the mean squared difference between the predicted score and the binary target. It is included as a preliminary diagnostic, but a reliability plot is still required before the sigmoid output can be interpreted as a calibrated probability.
